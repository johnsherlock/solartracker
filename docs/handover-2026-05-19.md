# Handover: Solartracker Rewrite Migration

Date: 2026-05-19

## Summary

This repository is now the canonical home of the PV Manager rewrite.

The rewrite was migrated from `johnsherlock/pv-manager` into
`johnsherlock/solartracker` on `main`, and the old Replit-era app was replaced
entirely.

## What Changed

- `solartracker/main` was force-updated to replace the old Replit app
- Rewrite-era history from `pv-manager` was preserved from the point the `v2`
  rewrite branch diverged onward
- The published repo no longer includes the legacy `V1/` app in `HEAD`
- Branch assumptions were updated from `v2` to `main` in the active story
  workflow skills, including `complete-story` and
  `plan-and-implement-story`

## Current Repo Shape

- Active app: `apps/web`
- Product and planning docs: `docs/`
- Repo-local workflow files: `.claude/`
- Canonical branch: `main`

## Product / Platform Context

- This is a Next.js rewrite app with Postgres/Drizzle, Google auth, MyEnergi
  integration, Vercel deployment, and Vercel-native background job direction
- Runtime and background work should stay Vercel-native
- GitHub Actions are for CI and repository automation, not product runtime jobs
- The previous `pv-manager` repo should now be treated as the old home, not the
  active delivery repo

## Backlog / Planning Context

Recent planning and backlog work already captured in-repo includes:

- `FE-019` for beta rollout must-haves
- `P-079` to `P-084` for beta launch gaps and rollout needs
- `P-083` as the repo migration and cutover story
- ADR `0010` capturing the decision to use Vercel-native background work rather
  than GitHub for product jobs

## Phase 1 Beta Priorities

The current Phase 1 beta emphasis is:

- strong public landing page
- hosting, domain, and deployment readiness
- onboarding and historical backfill flows
- daily cron and scheduled ingestion reliability
- provider health checks plus email alerts
- account deletion
- waitlist invite sending and resend flow
- selected UX polish, help, and explainer work
