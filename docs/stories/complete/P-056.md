# P-056: Replace daily_summaries with half-hourly interval_readings

## Objective

Replace the `daily_summaries` table with an `interval_readings` table that
stores 30-minute aggregated energy readings. This gives the financial
calculation layer accurate per-slot data so that self-consumed solar value,
import cost, and all other monetary metrics can be priced at the exact tariff
rate that applied at that time of day — rather than relying on day-rate
simplifications or pre-aggregated band breakdowns.

This story is a prerequisite for `P-054`. The financial model rework in
`P-054` assumes per-slot data is available.

## Background

The current `daily_summaries` table stores one row per installation per day.
Import is split into tariff-period buckets (`bandBreakdownJson`) but
generation, export, and immersion are daily totals only. This makes it
impossible to accurately price self-consumed solar — the best available
approximation is a flat day rate, which meaningfully understates value when
generation coincides with peak or higher-rate periods.

MyEnergi returns minute-level data for all metrics (import, generation, export,
immersion diverted, immersion boosted). The daily job already normalises this
into `MinuteReading[]` with all fields present. It then collapses everything
into a single daily row and discards the intermediate data.

The fix is to persist a 30-minute aggregation instead. 30-minute granularity
is sufficient because the tariff schedule is a 336-slot weekly grid (7 days ×
48 half-hour slots) — tariff boundaries always fall on half-hour marks, so
aggregating minutes to 30-minute slots is lossless for financial purposes.
Storing at minute level (1440 rows/day) would be 30× more data with no
financial benefit.

## Scope

### Schema

- Add `interval_readings` table:
  - `id`, `installation_id` (FK to `installations`)
  - `interval_start` (`timestamptz`, UTC start of the 30-min slot)
  - `import_kwh`, `generation_kwh`, `export_kwh`, `immersion_diverted_kwh`,
    `immersion_boosted_kwh`, `consumed_kwh` — all `numeric(10, 6)`
  - `reading_count` (`smallint`) — number of minute readings that contributed
    to this slot (0–30); used to detect partial slots
  - Unique constraint on `(installation_id, interval_start)`
  - Index on `(installation_id, interval_start)`
- Drop `daily_summaries` table
- Remove the `dailySummaries` relation from `src/db/relations.ts`
- Remove `dailySummaries` from `src/db/schema.ts`
- Create the corresponding Drizzle migration

### Daily job (`src/jobs/daily-summary.ts`, `src/jobs/derive-summary.ts`)

- Replace `deriveDailySummaryFields` / `deriveDailySummaryFieldsScheduled` /
  `deriveBandBreakdown` with a single `aggregateToIntervalReadings` function
  that groups `MinuteReading[]` into 30-minute UTC slots and returns one
  `IntervalReading` per slot with all metrics summed and `reading_count` set
- Remove tariff context loading from the job entirely — tariff rates are now
  applied at query time, not write time, so `loadTariffContextForDate` and all
  its DB queries are no longer needed at ingestion
- Replace `upsertDailySummary` with `upsertIntervalReadings` — upsert up to 48
  rows per installation per day (fewer on DST spring-forward days; more on
  fall-back days — use `expectedMinutesForDay` to know how many slots to expect
  and whether the day is complete)
- Update the catch-up job to determine which days to skip by checking whether
  `interval_readings` already has a full set of rows for that date, rather than
  checking `daily_summaries`
- Retain the date/timezone helpers in `derive-summary.ts`
  (`getLocalDate`, `getPreviousLocalDate`, `isAfterMidnightBuffer`,
  `expectedMinutesForDay`) — these are still used by the job

### Range history read path (`src/range/loader.ts`, `src/range/billing.ts`)

- Replace `loadDailySummaryRowsForRange` with `loadIntervalReadingsForRange`
  returning raw `IntervalRow[]` ordered by `interval_start` for the requested
  date range
- Replace `loadEarliestSummaryDate` with `loadEarliestIntervalDate` — queries
  `min(interval_start)` from `interval_readings` for the installation and
  returns it as a local date string using the installation timezone
- Remove the `DailySummaryRow` type; replace with an `IntervalRow` type
- Rewrite `computeRangeSummary` to work from `IntervalRow[]`:
  - Group intervals by local date (derived from `interval_start` + installation
    timezone) to produce per-day series entries for the charts
  - For each slot's import cost: call the existing `getScheduledRateForInterval`
    (already in `src/domain/billing.ts`) to resolve the applicable tariff rate
    for that UTC timestamp against the installation's weekly schedule, then
    apply discount and VAT
  - Self-consumed solar per slot: `max(0, generation - export - immersion_diverted)
    × slot_rate × discount × vat` — this is now exact, not estimated
  - Export credit: `export_kwh × export_rate` (flat rate, unchanged)
  - Fixed charges: continue to be applied per day using
    `fixedChargeContributionForDate` (unchanged)
  - Produce the same `RangeSummaryPayload` output shape — field renames and
    metric model changes are deferred to `P-054`
- Remove the `note` field (`'banded-daily-rate' | 'simplified-daily-rate'`)
  from `RangeSummarySection` and `RangeSummaryPayload` — it is meaningless
  once all slots are exactly priced; remove any UI references to it in
  `RangeHistoryScreen.tsx`
- A day is considered partial when `expectedMinutesForDay` for that date
  indicates more minutes than `reading_count` × 30 across the day's slots, or
  when the number of slots is less than `expectedMinutesForDay / 30`

### Domain billing cleanup (`src/domain/billing.ts`)

- Remove `calculateBillingFromDailySummaries` and
  `calculateBillingFromDailySummariesScheduled` — these functions operated on
  daily summary rows and are no longer called from any active path
- Remove the `DailySummaryForBilling` and `DailySummaryForBillingScheduled`
  types
- Retain `getScheduledRateForInterval`, `resolveTariffVersion`,
  `fixedChargeContributionForDate`, `calculateBillingPeriod`, and all other

## Acceptance Criteria

- `interval_readings` table exists with the schema above; `daily_summaries`
  and all its schema references are gone
- The daily job writes up to 48 interval rows per installation per day (46 on
  spring-forward days, 50 on fall-back days) and no longer writes to or reads
  from `daily_summaries`
- The catch-up job correctly populates `interval_readings` for historical dates
- Range History loads and displays correctly, drawing all data from
  `interval_readings`
- Import cost for a given day uses the exact tariff rate for each 30-minute
  slot, not a flat day rate or band breakdown
- Self-consumed solar value per slot is priced at the slot's actual tariff
  rate, not the day rate
- Partial day detection is DST-aware (spring-forward = 46 expected slots,
  fall-back = 50)
- No references to `daily_summaries` remain anywhere in active application code
- All tests pass; removed functions have their tests removed; new functions
  have focused tests

  implemented; used for DST-aware slot-count expectations
- Existing tariff schema (`tariff_plan_versions`, `tariff_price_periods`,
