# P-050: Build Location and notification-preferences settings flows

## Objective

Implement the remaining global non-investment Settings screens so Location and
notification preferences become real, user-editable parts of Settings
instead of placeholders.

## Scope

- Build the `/settings/location` route/screen and save flow
- Build the `/settings/notifications` route/screen for the first notification
  preference categories
- Location:
  - reuse the existing location capture model at no more precision than the
    weather/daylight features need
  - support editing, saving, and re-geocoding from Settings
  - surface clear error treatment when geocoding fails
- Notifications:
  - implement simple on/off preferences for the first categories defined by `U-052`
  - keep tariff-related language and behavior aligned with tariff validity
    reminders rather than supplier contracts
  - default categories to explicit on/off values so the section is never
    treated as incomplete
- Implement the first in-app stale-tariff CTA treatment on Live, History, and
  Range History when tariff validity is within 7 days of ending or has already
  lapsed
- Update the Settings home cards and setup progress so these domains reflect
  real completion state instead of placeholders
- Support clearing/removing saved setup values where appropriate and return the
  affected domain to incomplete when minimum data no longer exists

## Out of Scope

- Outage/anomaly notification delivery
- Multi-channel notification management
- Weather or solar-context redesign beyond the location edit path
- Full delivery/trigger implementation for every notification preference
  category beyond the first in-app stale-tariff CTA treatment

## Acceptance Criteria

- Users can open real Location and Notifications screens
- Users can edit Location from Settings using the existing location model
- Users can clear/remove saved setup values where the UX allows it, and setup
  completion updates accordingly
- Geocode failure states are recoverable and clear
- Notification preferences are editable and saved as explicit on/off values for
  the first defined categories
- Tariff-related notification wording is framed around tariff validity
- A warning CTA appears on Live, History, and Range History when tariff
  validity is within 7 days of ending or has ended
- Settings home no longer shows these domains as generic placeholders
