# P-075: Build all-time metric leaderboard and shared signed-in header nav

## Objective

Add a dedicated Leaderboard page that ranks the top five recorded days for each
metric already supported by Calendar View, and use the work to consolidate the
signed-in header into one shared navigation shell that exposes Leaderboard and
Settings consistently across the app.

## Scope

- Add a signed-in `/leaderboard` route in `apps/web`
- Reuse the same metric set already used by Calendar View, including the same
  metric names and explanatory copy where possible
- Render one card per supported metric
- Each leaderboard card should include:
  - metric name
  - short metric explanation consistent with Calendar View wording
  - top five recorded days of all time for that metric
- Each ranked day entry should include enough context to be useful at a glance,
  such as:
  - full date shown in a friendly format such as `Mon 23rd July 2024`
  - metric value in the correct unit or currency
  - clear missing-data or trust wording if the ranking is constrained by
    incomplete history
- Render the ranked entries as a table within each metric card
- Clicking a ranked row should open that day's Historical Day screen
- Update Calendar View's current best-day decoration so it no longer shows one
  generic trophy for only the top day:
  - show distinct 1st / 2nd / 3rd medal treatments on the calendar for the
    top three ranked days of the active metric
  - keep the medal logic aligned with the same ranking rules used by the new
    leaderboard
- Add a shared signed-in header component or layout wrapper used across the
  main product pages rather than letting each page maintain its own header
  treatment
- Add persistent header links for:
  - Leaderboard
  - Settings
- Ensure the shared header still supports the existing page-level controls that
  need to remain local, such as date or range controls that belong below the
  app-level nav rather than inside it
- Add automated coverage for leaderboard ranking/mapping logic and shared
  header navigation states

## Implementation Notes

- The user avatar ("J") present in existing page headers is intentionally
  removed when migrating to the shared header. There is no user avatar system
  yet and the hardcoded initial adds no value — dropping it keeps the shared
  header clean and avoids a misleading affordance.

## Out of Scope

- Streaks, badges, percentile systems, or social-sharing treatment
- User-configurable leaderboard formulas or custom metric creation
- Cross-installation or public leaderboards
- Replacing the existing Calendar View or Range History metric-switching
  surfaces
- Redesigning each page's local content header beyond what is needed to adopt a
  shared app-level header

## Acceptance Criteria

- Signed-in users can open `/leaderboard`
- The page renders one card for each Calendar View metric using consistent
  metric naming and explanation text
- Each card lists exactly the top five recorded days across all available
  history for that metric
- Ranked entries show the date in a format like `Mon 23rd July 2024` plus the
  day value in the correct unit or currency
- Clicking a ranked row opens the corresponding Historical Day page
- Ranking behavior handles ties and incomplete-history caveats consistently
  enough that the page does not imply false precision
- Calendar View replaces the single best-day trophy treatment with distinct
  1st / 2nd / 3rd medal indicators that reflect the active metric's ranking
- Calendar View, Live, Historical Day, Range History, Overview, and Settings
  all use the shared signed-in header pattern where applicable
- The shared header exposes working links to Leaderboard and Settings on both
  desktop and mobile layouts
- Tests cover the leaderboard ranking transformation and at least one shared
  header navigation path

## Dependencies

- `FE-011`
- `P-057`
- Existing Historical Day route
- Existing signed-in Settings route/shell

## Notes

- This story is the natural follow-on to `P-057`, which intentionally deferred
  ranking-style exploration from the first Calendar View launch.
- The leaderboard should feel like a companion discovery surface for Calendar
  View, not a gamified detour.
- The calendar medal treatment should reinforce the leaderboard relationship:
  the top three highlighted days on the calendar should match the same metric
  ranking logic shown on the leaderboard.
- The shared header change is intentionally bundled here because Leaderboard and
  Settings need durable app-level discoverability rather than one-off page
  links.
