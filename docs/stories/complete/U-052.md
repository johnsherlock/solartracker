# U-052: Define Location and notification-preferences settings UX

## Objective

Define the remaining global non-investment Settings domains so Location and
notification preferences can replace their placeholder states with clear
real-world edit flows that stay tightly within the beta scope.

## Scope

- Define the `/settings/location` screen
- Define the `/settings/notifications` screen as a simple notification
  preferences home rather than a fully featured notification center
- Define the completion rules for:
  - Location
  - notification preferences
- Define how users can clear/remove previously entered setup values in each
  domain and how that affects completion state
- Location:
  - reuse the existing exact/approximate model where relevant, but do not
    require street-level capture if weather/daylight context does not need it
  - keep precision only as strong as weather/daylight features require
  - define edit, save, geocode-success, geocode-failure, and unset states
- Notifications:
  - define the first user-manageable preference categories
  - keep tariff wording aligned with tariff validity, not supplier contracts
  - keep each category to a simple on/off preference in the first pass
  - default each category to on once the user reaches Settings
  - include the first-pass categories:
    - tariff end-date reminder notification (7 days before tariff validity ends)
    - missing-data notification (when daily data coverage falls below 90%)
    - generation notifications for highest generation/export day, week, or
      month of the year
    - import notifications for highest/lowest import day, week, or month of
      the year
- Define which of those categories are preference capture only in this story
  versus which require later delivery/trigger work in follow-on features
- Define the relationship between notification preferences and in-app CTA
  treatment for stale tariff coverage, including a warning CTA on Live,
  History, and Range History when tariff validity is within 7 days of ending
  or has already lapsed
- Define the Settings-home card treatment and value-unlock copy for each section

## Out of Scope

- Outage/anomaly notification delivery
- Notification delivery-channel preferences
- Admin/operator settings
- Implementing all notification triggers or delivery flows described by the
  preference model; some categories may remain preference capture only for now

## Acceptance Criteria

- Location and notification-preference flows are documented clearly enough to implement
  without reopening their basic scope
- Location explicitly stays no more precise than the weather/daylight features
  require and documents save vs geocode-failure behavior clearly
- Notification wording uses tariff-validity language, not contract language
- The first-pass notification categories, default states, and saved-summary
  behavior are defined clearly enough to implement the Settings screen now even
  where actual delivery work is deferred
- Settings-home completion rules and summary states are defined for both domains
- Clear/remove behavior is documented where it is supported, including
  returning a domain to incomplete when appropriate
- `Location` completion is based on a saved resolved location; `Notifications`
  are never incomplete because the categories default to explicit on/off values
- In-app stale-tariff CTA behavior is defined for Live, History, and Range
  History when tariff validity is close to ending or has ended
- Desktop and mobile behavior are documented
