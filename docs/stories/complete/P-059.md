# P-059: Add priced daily rollup for Range History

## Objective

Restore a fast day-level reporting path for Range History by deriving and
persisting a tariff-priced daily rollup from raw half-hour `interval_readings`,
so the `/range` screen no longer has to price raw interval rows directly on
every normal page load.

## Scope

- Design and add a derived daily priced summary layer for one installation-day
- The rollup must be derived from raw half-hour interval data and current tariff
  history
- Store the day-level fields needed by Range History, including:
  - generated kWh
  - import kWh
  - export kWh
  - consumed kWh
  - immersion-diverted kWh
  - partial/missing-day signals needed by the range screen
  - import cost
  - export credit/value
  - self-consumed solar value
  - counterfactual without-solar import cost
  - fixed charges
  - daily net-cost / savings outputs
- Update the daily-summary ingestion path so captured days also populate or
  refresh this rollup
- Preserve an explicit `isPartial` flag on each installation-day rollup row,
  with `isPartial = true` when captured minute-level data for that local day is
  below 90% of the expected minutes for that day (DST-aware)
- Update the main bounded-range `/range` read path to load from the daily
  priced rollup instead of raw `interval_readings`
- Keep raw `interval_readings` unchanged as the source of truth

## Out of Scope

- `All` mode optimization
- Final tariff-edit invalidation/rebuild workflow
- Replacing raw interval storage
- Reworking the user-facing metric definitions from `P-054`

## Acceptance Criteria

- A persisted daily priced summary exists for Range History consumption
- The summary is built from raw half-hour interval data and current tariff
  definitions rather than hand-entered day totals
- Dynamic tariff price-period counts do not block the design because interval
  slot pricing is resolved before day totals are stored
- Partial-day handling is explicit and stable: the rollup persists `isPartial`
  using the shared `< 90% of expected day minutes captured` rule rather than
  ad hoc UI-only heuristics
- The bounded-range `/range` path reads from the daily priced summary rather
  than repricing raw interval rows on every request
- The page returns the same effective day-level financial outputs for covered
  dates as the raw interval-based path, within normal rounding tolerance
- Raw `interval_readings` remain intact for future rebuilds

## Dependencies

- `P-056` raw half-hour interval model
- Existing tariff version / price period / fixed-charge model
