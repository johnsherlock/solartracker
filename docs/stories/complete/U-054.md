# U-054: Define Range History financial metric model and narrative

## Objective

Define a clearer financial interpretation model for Range History so the page
can explain, for any selected period:

- what financial value solar created
- what happened to the energy bill
- what solar financing cost
- whether the system was ahead or behind overall

This story should replace ambiguous "solar savings" language with explicit
metric definitions and a clearer narrative hierarchy.

## Scope

- Define the primary hero narrative for the selected period as:
  - `Solar created EUR X of value`
  - `EUR Y came from self-consumption and EUR Z came from export`
  - `Repayments due in this period were EUR A`
  - `Your net solar position for this period was EUR B`
- Define the first-pass financial metric groups for Range History:
  - `Energy value`
  - `Bill impact`
  - `Investment payoff`
- Define which metrics belong in the hero layer versus supporting detail
- Define the intended meaning, formula basis, and plain-English explanation for
  each first-pass metric
- Define tariff-accuracy rules for the metric set, including:
  - which metrics must use the actual tariff structure available for the period
  - which metrics may use an estimated or counterfactual method
  - how estimated or simplified tariff treatment must be labeled in the UI
- Define which metrics are:
  - measured totals
  - tariff-priced estimates
  - counterfactual estimates
- Define which existing Range History metrics should be retired, relabeled, or
  preserved only as secondary detail

## First-Pass Metric Model

### 1. Hero metrics

The selected period should lead with these outcomes:

1. `Total solar value`
   Meaning: the total financial value created by solar in the selected period.
   Formula basis: `self-consumed solar value + export credit`

2. `Self-consumed solar value`
   Meaning: the estimated value of generated energy used in the home instead of
   being imported from the grid.
   Formula basis: self-consumed solar kWh priced using the applicable avoided
   import tariff treatment defined for the period.

3. `Export credit`
   Meaning: the tariff-priced value earned from exported energy in the selected
   period.
   Formula basis: exported kWh priced using the applicable export tariff.

4. `Repayments`
   Meaning: scheduled solar repayments due in the selected period.
   Formula basis: payment schedule overlap for the selected period.

5. `Net solar position`
   Meaning: whether solar was ahead or behind overall in the selected period.
   Formula basis: `total solar value - repayments`

### 2. Supporting metric groups

#### Energy value

These explain what solar created financially.

- `Self-consumed solar value`
- `Export credit`
- `Total solar value`

#### Bill impact

These explain what happened to the electricity bill.

- `Import bill`
  Meaning: actual tariff-priced cost of imported electricity before export
  credit.
- `Net energy bill`
  Meaning: actual import bill minus export credit.
- `Import bill without solar`
  Meaning: modeled counterfactual import bill if the same demand occurred
  without solar generation.
- `Bill reduction from solar`
  Meaning: `import bill without solar - net energy bill`

#### Investment payoff

These explain whether the system is paying for itself.

- `Repayments`
- `Net solar position`
- `Recovered so far`
  Meaning: cumulative recovered value from recorded history using the existing
  `U-051` whole-system model.
- `Approximate payoff outlook`
  Meaning: rough guidance derived from historical recovery behaviour, not a
  promise.

## Metric Classification Rules

### Measured totals

These come directly from stored energy totals and are not monetary by
themselves:

- imported kWh
- generated kWh
- exported kWh
- immersion diverted kWh

### Tariff-priced estimates

These are monetary metrics that should use the real tariff structure we have
for the selected period:

- import bill
- export credit
- net energy bill
- self-consumed solar value
- total solar value

### Counterfactual estimates

These depend on a modeled no-solar or avoided-cost scenario and must never be
presented as raw actuals:

- import bill without solar
- bill reduction from solar

## Tariff-Accuracy Rules

1. Actual tariff-priced metrics must use the real tariff structure available
   for the covered days wherever stored data supports that precision.
   This includes:
   - actual import cost
   - export credit
   - net energy bill

2. The product must not silently flatten actual tariff-priced metrics to one
   day-rate assumption if schedule/band data exists for the relevant days.

3. Counterfactual metrics may still use an estimation method, but the method
   must be explicit and the UI must label the result as estimated or modeled
   where needed.

4. If a metric depends on a simplified no-solar assumption, the wording must
   make clear that it is a counterfactual estimate rather than a supplier-bill
   reconstruction.

## Wording Rules

1. `Total solar value` includes both self-consumption value and export credit.
   The UI must never imply that export credit is additional on top of that same
   total.

2. `Bill reduction from solar` is not the same concept as `total solar value`.
   It belongs in `Bill impact`, not in the hero meaning of "what solar created."

3. `Repayments` are financing costs, not part of the electricity bill.
   The UI must not blend them into `net energy bill`.

4. `Net solar position` is the selected-period payoff outcome:
   `total solar value - repayments`.
   It is not the same thing as `net energy bill`.

5. The existing headline label `Solar savings` should be retired as a primary
   Range History KPI because it currently blends together concepts that should
   now be separated more clearly.

## Existing Metrics To Retire Or Demote

- Retire `Solar savings` as the primary hero KPI
- Preserve `bill reduction from solar` only as a supporting bill-impact metric
- Preserve `Recovered so far` and `payoff outlook` as supporting investment
  metrics rather than page-defining summary totals
- Preserve `export credit` as its own explicit supporting metric, but only in a
  way that is consistent with `total solar value`

## Out of Scope

- Final visual design treatment for the full page
- Immersion trade-off metrics beyond identifying where they belong conceptually
- Supplier-bill reconciliation or tax/accounting treatment
- New forecasting logic beyond the already agreed payoff guidance

## Acceptance Criteria

- Range History has a documented hero financial story for the selected period
- The first-pass metric catalogue is defined with explicit formulas or formula
  bases and plain-English descriptions
- The story explicitly defines which financial metrics must be priced using the
  actual tariff data available, and which are allowed to remain estimated or
  counterfactual
- The product clearly distinguishes energy value, bill impact, and investment
  payoff rather than blending them under one overloaded savings number
- The intended meaning of `self-consumed solar value`, `total solar value`,
  `bill reduction`, and `net solar position` is unambiguous
- The story explicitly retires or demotes the current ambiguous `Solar savings`
  framing in Range History
- The story identifies which current labels or calculations are misleading and
  need to be replaced or demoted
- The resulting spec is clear enough to implement without reopening the core
  financial terminology
