# P-057: Build year-calendar history view

## Objective

Add the first dedicated Calendar View surface so users can scan an entire year
of daily performance at once, switch between key energy/value metrics, and
navigate fluidly between day detail, monthly range history, and yearly range
history.

## Scope

- Add a signed-in `/calendar` route in `apps/web`
- Render a 31 x 12 matrix:
  - days `1..31` across the top
  - months down the side
  - one cell per valid calendar day in the selected year
- Treat each day cell as a compact vertical bar whose height is relative to the
  highest day in the selected year for the selected metric
- Support switching the displayed metric between:
  - generation kWh
  - generated energy consumed on-site (kWh)
  - generated energy consumed on-site (value)
  - total import kWh
  - total import cost
  - export kWh
  - export value
  - immersion kWh
  - net solar position
  - pro-rata daily payment covered (i.e. did this day generate enough savings to cover the pro-rata cost of the day. Anything > 100% of the pro-rata rate is a full bar. Anything less is whatever % of the pro-rata rate the savings covered).
- Animate bar size and color changes when the selected metric changes
- Show the selected year's total for the active metric
- Show a tooltip on hover with the day value or missing-data/tariff state
- Navigation behavior:
  - clicking a day opens `/history/[date]`
  - clicking a month opens the corresponding `/range` month
  - clicking the year opens the corresponding `/range` year
  - previous / next year controls move between available years
- Reuse the existing range-history yearly payload shape rather than creating a
  second yearly aggregation model
- Share yearly payload caching between Range History and Calendar View so:
  - loading a year in `/range` can warm `/calendar`
  - loading a year in `/calendar` can warm `/range`

## Out of Scope

- Annual recap / wrap-up storytelling
- Ranking, streaks, percentile systems, or AI-generated highlights
- Editing data directly from the calendar
- Cross-year comparison layouts
- New data-fetch backends beyond the existing range-history source data

## Acceptance Criteria

- `/calendar?year=YYYY` loads a year-calendar screen for signed-in users
- The year grid renders valid days only; non-existent dates are visually empty
- Current-year future dates are visibly non-interactive
- The metric switcher updates:
  - bar heights
  - bar colors
  - active-metric yearly total
- Bar height is normalized to the peak day in the selected year for that metric
- Hovering a populated day reveals the metric value in the installation
  currency/unit as appropriate
- Clicking a populated day opens that day's Historical Day screen
- Clicking a month label opens the corresponding monthly Range History view
- Clicking the year label opens the corresponding yearly Range History view
- Moving between years respects the earliest available history and does not go
  beyond the current year
- Range History and Calendar View use a shared client-side yearly cache module
  rather than duplicating separate year-prefetch logic
- Automated coverage exists for the calendar metric/value mapping and year-model
  normalization logic

## Dependencies

- `FE-003` Historical Day View
- `FE-006` Range History Screen
- Existing `/api/range` yearly data contract
- `P-056` interval-based range data foundation
