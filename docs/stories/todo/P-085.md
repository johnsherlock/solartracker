# P-085: Register beta domain and wire external service ownership

## Objective

Choose and register the canonical beta domain, establish one clear DNS home,
and complete the external ownership/setup prerequisites needed so Vercel,
Google OAuth, and email delivery can all use the real production host rather
than temporary defaults.

## Scope

- Choose the registrar / DNS home for the first beta domain
- Register the canonical domain and document the choice
- Decide the production host shape, including:
  - apex vs `www`
  - support mailbox shape
  - any sending subdomain used for email delivery
- Document the DNS records and ownership checks required for:
  - Vercel custom-domain attachment
  - Google OAuth authorized domain and redirect URI setup
  - Resend sending-domain verification
- Make the operator-facing setup sequence explicit enough that `P-079` can
  build directly on it without rediscovering domain assumptions

## Out of Scope

- Completing the full deploy/runbook work covered by `P-079`
- Building a full support system
- Writing legal/privacy pages unless needed only as placeholders for external
  service setup

## Acceptance Criteria

- A canonical beta domain is registered and documented in-repo
- DNS is managed from one agreed home
- The intended production host shape (`apex`, `www`, support mailbox, sending
  subdomain if any) is explicit
- Vercel custom-domain requirements are documented against the chosen domain
- Google OAuth authorized-domain and redirect-URI requirements are documented
  against the chosen domain
- Resend sending-domain verification requirements are documented against the
  chosen domain
- The story leaves no ambiguity about which domain subsequent rollout stories
  should target

## Dependencies

- `FE-019`
- `FE-012`
- Existing public landing/auth/email assumptions in `apps/web`

## Notes

- This is the first real rollout blocker because several later setup steps
  become guesswork until the production domain actually exists.
- Keep the first beta conservative: one canonical public host, one clear DNS
  home, and one support-email shape are more important than flexibility.
