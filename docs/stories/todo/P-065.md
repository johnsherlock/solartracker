# P-065: Build the Overview signed-in landing page

## Objective

Implement the first production Overview screen in `apps/web` so signed-in users
arrive on a summary-first home that surfaces finance outcome, setup progress,
trust/freshness, live context, and clear next actions.

## Scope

- Build the Overview route and make it the intended default signed-in landing
  destination
- Implement the first summary modules defined by the signed-in design docs,
  including:
  - setup-progress / unlock-more strip
  - high-level financial KPIs
  - live snapshot card
  - trust / freshness summary
  - interpretation panel
  - shortcut CTAs into Live, Historical Day, Range History, Tariffs, Data
    Health, or setup as appropriate
- Ensure provider-only and setup-incomplete users get useful prompt-card states
  rather than broken or empty finance modules
- Reuse existing data paths where possible, adding any minimal server-side
  composition needed for Overview-specific summary loading
- Add automated coverage for the key routing, gating, and signed-in state rules

## Out of Scope

- A chart-heavy dashboard redesign
- Public landing or unauthenticated welcome work
- Deep new financial-model work beyond reusing established metric definitions
- Advanced recommendation engines or long-form reporting modules

## Acceptance Criteria

- Signed-in users can land on a real Overview screen in `apps/web`
- The screen communicates high-level financial state, trust/freshness, live
  context, and setup progress without requiring chart interpretation first
- Missing tariff or finance setup is handled with clear unlock messaging and
  useful CTAs
- The live snapshot remains useful even when savings/payback are gated
- Navigation from Overview into the deeper product areas feels coherent on both
  desktop and mobile
- Tests cover the main signed-in landing states and CTA/routing behavior
