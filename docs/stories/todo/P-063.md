# P-063: Add tariff-period totals and cost breakdown reporting

## Objective

Let users inspect energy totals and priced totals for the dynamic price periods
within a tariff version's validity window, so they can answer questions such as
"how much import happened in this tariff's night/peak/day periods?" without
falling back to raw interval analysis.

## Scope

- Add a reporting path for tariff-version-duration totals grouped by dynamic
  `tariff_price_periods`
- Support energy totals at minimum:
  - import kWh
  - optionally self-consumed solar kWh and no-solar import kWh if needed for
    meaningful repricing/reporting
- Support priced totals for each period using the tariff rates applicable to
  that version
- Keep the model compatible with dynamic user-defined price periods rather than
  assuming fixed `day` / `night` / `peak` columns
- Decide whether this should be:
  - on-demand reporting from raw `interval_readings`
  - persisted child rows under `daily_priced_rollups`
  - or another equivalent dynamic rollup model
- Make clear how period-level historical reporting interacts with tariff edits
  and `P-060` invalidation/rebuild rules

## Out of Scope

- Battery what-if simulation
- A full redesign of the existing Range History KPI narrative
- Reintroducing hardcoded legacy tariff-band assumptions into the runtime model

## Acceptance Criteria

- The intended dynamic data model for tariff-period totals is documented well
  enough to implement without reopening the core storage approach
- The solution supports an arbitrary number of user-defined price periods per
  tariff version
- Users can retrieve totals for a tariff version's validity window without
  depending on hardcoded `day` / `night` / `peak` columns
- The story documents whether rate-only tariff changes can be repriced from the
  persisted model or still require a rebuild from raw intervals
- Any persisted reporting layer keeps historical period identity stable enough
  to remain trustworthy after later tariff edits

## Dependencies

- `FE-015`
- `P-059`
- `P-060`
- Existing schedule-based tariff and `tariff_price_periods` model

## Notes

- This is a useful analytical/reporting enhancement, but it is not currently
  essential for beta launch.
- A likely direction is a parent/child rollup shape where the day-level parent
  row keeps overall totals and child rows capture per-price-period energy
  buckets keyed by `tariff_price_periods.id` plus any required historical
  snapshots.

### Status: Deferred
