# Q-015: Validate missing-day estimation behavior and disclosure rules

## Objective

Protect the first estimated-backfill feature with test coverage and worked
examples so the estimation model, stored flags, and user-facing disclosure
rules do not drift apart.

## Scope

- Add worked examples for at least:
  - a short missing gap
  - a longer gap with lower confidence
  - a case where no reasonable estimate should be shown
- Validate that persisted estimated days stay distinguishable from measured days
- Validate that Range History totals and visual states behave correctly with the
  estimates toggle both on and off
- Validate that Historical Day remains unchanged for missing dates

## Out of Scope

- Creating a second estimation algorithm just for testing
- Performance optimization of the estimation job itself

## Acceptance Criteria

- Automated coverage protects the first-pass estimation behaviors and trust
  rules
- Tests assert that estimate-aware range totals are labeled and distinguishable
  from measured-only totals
- Tests assert that missing Historical Day behavior is unchanged
- At least one worked example acts as living documentation for the intended
  estimate flow
