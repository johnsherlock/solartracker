# P-068: Deliver configurable best-day notifications

## Objective

Drive re-engagement by notifying users when the rollup process discovers a new
best day for one of the metrics they care about, such as generation,
self-consumption, or solar value.

## Scope

- Define the first best-day notification trigger rules against persisted daily
  summaries or rollups
- Support configurable user preferences for which achievement categories should
  trigger notifications
- Support first-pass metric categories such as:
  - generation
  - self-consumption
  - solar value
  - export
  - other equivalent standout metrics if already present in the rollup model
- Distinguish between "best this year" and "best all time" where the metric and
  data coverage make that claim trustworthy
- Include clear deep links back into the app so the notification encourages
  exploration rather than feeling like an isolated badge

## Out of Scope

- Social sharing or public brag-card generation
- A full gamification or streak system
- Metrics that cannot be trusted yet because the underlying model or historical
  coverage is incomplete

## Acceptance Criteria

- Users can opt in or out of best-day notifications by metric category
- The system can detect and notify on at least one trustworthy "best this year"
  and one trustworthy "best all time" case
- Notification wording makes clear what metric was broken and what comparison
  set it beat
- The app avoids noisy duplicate sends for the same record event

## Dependencies

- `FE-018`
- Existing saved notification preferences
- Persisted daily summaries or priced daily rollups that support the chosen
  metrics
