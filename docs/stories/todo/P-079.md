# P-079: Finalize beta environment, domain, and launch runbook

## Objective

Close the gap between the rewrite's current code/runtime expectations and the
operational setup required to run a real beta by documenting and wiring the
domain, environment variables, callback URLs, cron auth, email sender config,
and basic launch/recovery runbook.

## Scope

- Audit the real runtime configuration expected by `apps/web`
- Update `.env.example` and/or supporting setup docs so the required beta
  environment variables are explicit
- Document the production and preview configuration needed for:
  - database connection
  - Google OAuth callbacks
  - auth/session secrets
  - cron authentication secret
  - provider credential encryption key
  - email sender / delivery provider
  - geocoding key
- Document the expected domain and DNS/application configuration for the beta
- Define a short operator runbook covering:
  - initial environment setup
  - deploy
  - smoke checks after deploy
  - what to inspect first when onboarding, cron, or email delivery fails

## Out of Scope

- Replacing the chosen hosting platform
- Full observability platform rollout beyond the first beta runbook
- Writing generic local-development docs unrelated to beta deployment

## Acceptance Criteria

- The real beta environment requirements are documented in-repo
- Callback, domain, cron, and email setup steps are explicit enough to follow
  without guessing
- The launch runbook includes a concrete post-deploy smoke-check list
- The runbook includes first-response guidance for the most likely beta issues
- The work closes the current mismatch between code-level env usage and the
  minimal `.env.example`

## Dependencies

- `FE-012`
- Existing auth, cron, and email implementation in `apps/web`

## Notes

- This is deliberately boring but launch-critical. A small beta gets fragile
  fast if domain, secrets, callbacks, and operator checks only live in memory.
