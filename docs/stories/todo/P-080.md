# P-080: Apply first beta screen tidy-up from product observations

## Objective

Capture the concrete product-review observations that are small enough to fix
before beta launch but visible enough to undermine confidence if they are left
untouched, then implement the agreed tidy-up pass across the affected screens.

## Scope

- Turn the current observation list into one explicit checklist of launch-
  blocking polish items
- Apply the agreed fixes across the affected surfaces, expected to include a
  mix of:
  - copy clarity
  - CTA labeling
  - empty / blocked / setup-incomplete messaging
  - spacing or hierarchy tidy-up
  - obvious trust/explainer gaps
- Keep the work intentionally scoped to polish and clarity improvements rather
  than broad redesign
- Record which observations were intentionally deferred so the polish pass does
  not turn into an unbounded cleanup bucket

## Out of Scope

- New feature work that belongs in separate stories
- Reworking major layouts from scratch
- Motion, branding, or landing-page ambition beyond the agreed observation list

## Acceptance Criteria

- A concrete checklist exists for the product-review observations included in
  this pass
- The agreed launch-blocking issues are fixed on the relevant screens
- The implementation remains traceable to the observation list rather than
  introducing unrelated redesign work
- Any intentionally deferred observations are called out explicitly

## Dependencies

- `FE-019`
- The specific observation set agreed during beta-readiness review

## Notes

- This story exists to stop "just a few more tidy-ups" from leaking into every
  other implementation story.
