# U-059: Define public landing-page narrative, layout, and motion direction

## Objective

Define the narrative, copy structure, layout system, visual language, and
motion principles for a premium unauthenticated landing page that tells the
product story clearly while feeling modern, polished, and high-end.

## Scope

- Define the story arc for the public landing page, including:
  - hero message
  - supporting proof points
  - product-value sections
  - supported-setup expectations
  - trust/privacy messaging
  - primary calls to action
- Define the section order and content hierarchy for desktop and mobile
- Define the copy direction and key headlines for each section
- Define the visual and motion direction for premium presentation, such as:
  - scroll-revealed or scroll-transformed headlines
  - animated or staged product screenshots
  - parallax, pinning, or reveal behavior where appropriate
  - restrained but high-impact transitions between sections
- Define how the landing page should reference the app without feeling like a
  generic SaaS site or a shallow marketing shell
- Make clear which assets are required for implementation, such as screenshots,
  product mockups, illustration treatments, or motion placeholders

## Out of Scope

- Implementing the landing page in code
- SEO/content strategy beyond what the first product-led landing page needs
- A full brand system or long-form marketing-site architecture

## Acceptance Criteria

- The landing-page narrative is documented clearly enough to implement without
  re-opening the core message structure
- Desktop and mobile section order, module types, and CTA placements are
  defined
- Headline and supporting-copy direction are strong enough to guide real UI
  writing rather than leaving the implementation to invent the story ad hoc
- The motion and screenshot behavior is specific enough that implementation can
  aim for a premium, intentional result instead of generic scroll animations
- Required visual assets or placeholders are identified

## Dependencies

- `FE-009`
- Existing product/design context for the signed-in app and public beta model

## Notes

- The target feel is closer to a high-end product launch page than a plain
  signup screen, but the story still needs to stay honest and product-led.
- The page should persuade by making the product feel desirable and legible, not
  by turning into vague brand theater.

## Design Direction

The page should feel like a premium product launch for a serious home-energy
tool, not a generic SaaS marketing site. The emotional mix is:

- calm confidence rather than hype
- cinematic pacing rather than constant animation noise
- technical credibility rather than vague sustainability language
- editorial composition rather than boxed enterprise landing-page modules

The visual reference point is "instrument-grade product launch page":
atmospheric, dark, precise, and immersive, with the app shown as the hero asset
rather than decorative illustration.

### Brand Mood

- Primary tone: refined, intelligent, quietly ambitious
- Secondary tone: domestic energy made legible and valuable
- Avoid:
  - cartoonish eco branding
  - generic corporate-blue SaaS layouts
  - exaggerated "AI" visual tropes
  - abstract motion with no product meaning

### Visual Language

- Use a dark, high-contrast base with warm solar accents rather than neon tech
  colors
- The page should feel like dusk light hitting glass, metal, and dashboards:
  charcoal, deep navy, smoked teal, muted brass, warm amber, off-white
- Screenshots should sit inside elevated device-like frames or layered
  dashboard cards, not plain browser rectangles
- Layout should alternate between generous editorial spacing and tightly framed
  proof moments so the page breathes, then focuses

### Motion Philosophy

- Motion should reveal understanding, not just decorate
- Each transition should either:
  - sharpen the product story
  - stage a key product proof point
  - guide the user toward demo or sign-in
- Prefer slower, more luxurious movement with strong easing over twitchy
  micro-animation
- Mobile should keep the same intent but simplify depth, pinning, and layered
  transforms

## Narrative Strategy

The page should tell one clear story:

1. Solar owners can see generation but still struggle to understand value.
2. Solar Tracker turns noisy energy data into a financial and operational
   picture that feels immediately legible.
3. The product is real, read-only, and built for actual home setups rather than
   theoretical dashboards.
4. Visitors can either preview the experience in demo mode or request real beta
   access by signing in.

### Core Messaging Principles

- Lead with financial clarity, not generic monitoring
- Present the app as a premium analysis layer over an existing solar setup
- Be honest about current beta constraints:
  - invite-only beta
  - MyEnergi-first support
  - Google sign-in is the beta access request path
- Trust messaging should be explicit and calm:
  - read-only provider access
  - no device control
  - clear deletion/privacy posture

## Information Architecture

### Desktop Section Order

1. Hero
2. Product tension / "why this exists"
3. Hero screenshot stage
4. Value pillars
5. Range-value storytelling section
6. Live monitoring / trust / freshness section
7. Supported setup and beta model
8. Privacy and read-only proof
9. Demo + sign-in conversion band
10. Final CTA footer

### Mobile Section Order

Use the same story, but collapse it into a tighter rhythm:

1. Hero
2. Single primary screenshot
3. Product tension
4. Value pillars
5. Range-value proof
6. Live/trust proof
7. Supported setup
8. Privacy
9. Demo + sign-in CTA
10. Footer

Mobile should front-load the product image earlier so users see something real
before too much text.

## Section-by-Section Brief

### 1. Hero

Purpose:
Introduce the product as the clearest way to understand what a home solar
installation is actually doing financially and operationally.

Layout:

- Full-bleed opening with oversized headline on the left or center-left
- Right-side or lower staged product composition featuring layered screens
- Sticky top navigation with restrained branding and a visible sign-in CTA
- Primary CTA for demo, secondary CTA for sign-in / beta access

Headline direction:

- "See what your solar is actually worth."
- Alternate acceptable direction:
  - "The clearest picture of what your solar is doing."
  - "From live flow to real savings, in one view."

Supporting copy direction:

- Explain that Solar Tracker turns generation, import, export, tariff, and
  payback context into one readable product experience
- Keep this grounded and concrete rather than poetic

CTA treatment:

- Primary: `View demo`
- Secondary: `Sign in for beta`
- Small supporting line: `Invite-only beta. MyEnergi supported first.`

Motion:

- Headline reveals in two or three measured steps
- Product screens rise in with layered depth and slight parallax
- Background light gradient shifts subtly as the page settles

### 2. Product Tension

Purpose:
Name the problem in a way that makes the rest of the page feel necessary.

Message:

- Solar owners often have data, but not understanding
- Generation totals alone do not explain bill impact, export value, or whether
  the system is paying back the way it should

Layout:

- Editorial two-column block or staggered text panels
- One strong statement paired with three short tension points

Example copy direction:

- "Most solar dashboards stop at activity. They show movement, not meaning."
- Supporting points:
  - what you generated
  - what you imported anyway
  - what your exports were worth
  - how your tariff changed the result

Motion:

- Scroll-reveal lines or cards
- Mild horizontal drift or opacity sequencing only; no heavy effects

### 3. Hero Screenshot Stage

Purpose:
Prove immediately that the product has real UI depth and not just conceptual
promise.

Layout:

- Large staged composition using the strongest app screens
- One dominant screen with two supporting floating crops
- Prefer showing real product detail: live cards, charts, range summaries,
  savings/payback cues

Content emphasis:

- The main screenshot should make the product feel both premium and useful
- Labels and metrics visible in the mock should suggest:
  - live flow
  - tariff-aware value
  - historical insight

Motion:

- Slow parallax between layered screenshots
- Optional pinned section on desktop while text changes beside it
- Mobile version should use a single transformed image stack without pinning

### 4. Value Pillars

Purpose:
Translate the product promise into three memorable benefits.

Pillars:

1. `See the whole energy picture`
2. `Understand the money, not just the power`
3. `Trust what the app is telling you`

Guidance:

- Each pillar needs a tight headline and one sharp explanatory sentence
- Avoid feature laundry lists

Suggested copy direction:

- `See the whole energy picture`
  Solar generation, import, export, and household demand in one readable flow.
- `Understand the money, not just the power`
  Tariff-aware history, export value, and payback context that map to real
  household decisions.
- `Trust what the app is telling you`
  Freshness, read-only access, and setup-aware interpretation instead of black
  box scorecards.

Layout:

- Three asymmetrical cards or columns
- Cards should feel sculpted and premium, not repetitive pricing-card blocks

Motion:

- Staggered reveal
- Delicate hover lift on desktop

### 5. Range-Value Storytelling Section

Purpose:
Show that the product goes beyond live monitoring into meaningful historical
understanding.

Message:

- The product helps users understand long-range savings, export trade-offs, and
  payback direction, not just today's weather and wattage

Layout:

- Text paired with an oversized Range History or financial-summary visual
- Consider a scrollytelling structure where captions step through what the user
  learns from the screen

Copy direction:

- "Your best solar day is interesting. Your long-term value is what matters."
- Explain that the app surfaces how usage, export, tariff shape, and system
  performance combine over time

Motion:

- Highlight zones within the screenshot as text advances
- Use restrained spotlight or mask transitions instead of flashy callouts

### 6. Live Monitoring / Trust / Freshness Section

Purpose:
Balance the financial story with the immediacy of the live product.

Message:

- Users can also see what the system is doing right now
- Data recency and operational confidence matter; freshness should feel like a
  product strength, not hidden plumbing

Layout:

- Split section: live-product visual on one side, trust/freshness language on
  the other
- A small live-status ribbon or recent-data indicator can be shown as part of
  the screenshot treatment

Copy direction:

- "Live context when you want it. Historical clarity when you need it."
- Supporting points:
  - current generation/import/export
  - weather/daylight context
  - confidence about when the data last updated

Motion:

- Animated chart shimmer or subtle pulse in a live indicator
- Keep this understated; it should feel precise, not gamified

### 7. Supported Setup and Beta Model

Purpose:
Set expectations before conversion so the beta feels curated rather than vague
or exclusionary.

Message:

- This is an invite-only beta
- MyEnergi is supported first
- Google sign-in is how users request access

Layout:

- Compact section with strong typography and clear eligibility bullets
- Could include a small "Current beta shape" panel rather than a giant FAQ

Copy direction:

- "Built for real homes, starting narrowly on purpose."
- Explain that the product is beginning with supported setups so the experience
  stays trustworthy during beta

Motion:

- Minimal
- This section is about clarity, so avoid anything theatrical

### 8. Privacy and Read-Only Proof

Purpose:
Remove the most important trust objection before the user commits.

Required messages:

- Solar Tracker only reads provider data
- It never changes settings or controls devices
- Account/data deletion is available

Layout:

- Smaller, more intimate trust block with tighter spacing
- Can feel almost like a signed note or product principle card

Copy direction:

- "Read-only by design."
- Supporting sentence:
  "Solar Tracker is built to help you understand your system, not interfere
  with it."

Motion:

- Almost none
- A subtle fade or rise is enough

### 9. Demo + Sign-In Conversion Band

Purpose:
Offer the two main entry paths without ambiguity.

Hierarchy:

- Primary path: demo mode
- Secondary path: sign in for beta

Reasoning:

- Demo is the lower-friction action and best proof tool
- Sign-in remains essential, but should feel like the next committed step

Required copy:

- Demo is read-only
- Sign-in is the beta access request path
- Supported setup expectations remain visible

Layout:

- Two contrasting cards or a split-band layout
- One card should feel exploratory; the other should feel more committed

### 10. Final CTA Footer

Purpose:
Close with a concise, elegant restatement of the value proposition.

Headline direction:

- "Make your solar legible."
- Alternate:
  - "See the system. Understand the value."

Content:

- One-line recap
- CTA pair repeated
- Minimal footer links for terms/privacy if available

## Copy Style Guide

- Short, declarative, intelligent sentences
- Prefer concrete nouns over marketing abstractions
- Use "solar", "import", "export", "tariff", "savings", "payback", and
  "read-only" confidently where helpful
- Avoid:
  - "unlock"
  - "supercharge"
  - "revolutionize"
  - "AI-powered"
  - empty sustainability slogans

The product voice should feel like a smart operator explaining a genuinely
useful instrument, not a growth team writing conversion copy.

## CTA Strategy

Primary public CTAs:

- `View demo`
- `Sign in for beta`

Supporting CTA rules:

- `View demo` should appear in the hero, conversion band, and final CTA area
- `Sign in for beta` should appear in the hero, nav, conversion band, and final
  CTA area
- Avoid a separate `Request beta access` CTA label if the actual mechanism is
  Google sign-in; the copy should stay operationally honest

## Motion and Interaction Spec

### Required Motion Behaviors

- Hero headline reveal with staged line timing
- Layered screenshot entrance on load
- At least one major scroll-led product reveal section
- Gentle parallax or depth movement in screenshot compositions
- CTA hover states that feel polished and tactile

### Motion Guardrails

- No autoplay video required for v1
- No excessive scroll-jacking
- No dependency on motion for comprehension
- All key copy and CTAs must remain legible and usable with reduced motion
- Mobile should reduce layered transforms, pinned sequences, and blur-heavy
  effects

### Reduced-Motion Fallback

- Replace parallax with static compositions
- Replace staged scroll transitions with simple fades/rises
- Keep hierarchy, screenshots, and CTA clarity fully intact

## Screenshot and Asset Plan

Implementation should assume the need for curated visual assets rather than
raw screen grabs dropped into the page.

### Required Assets

- One premium hero composition built from real app screens
- One Range History / savings-focused screenshot
- One Live / current-flow screenshot
- Optional supporting crops for weather, payback, or trust/freshness detail
- Lightweight placeholder backgrounds or lighting textures for section staging

### Screenshot Guidance

- Use realistic but visually clean seeded data
- Favor days/ranges that make charts and savings states look understandable and
  attractive
- Avoid screenshots with unfinished labels, empty states, or placeholder text
- Screenshots should be art-directed:
  - cropped intentionally
  - color-balanced together
  - framed consistently

- The final implementation should preserve product honesty over dramatic flair
