# P-064: Build public welcome and demo entry flows

## Objective

Build the surrounding unauthenticated welcome and demo-entry flows around the
main public landing page so prospective users can move cleanly into sign-in,
beta-access, and read-only demo paths without confusion.

## Scope

- Build or refine the non-landing public entry flows that sit around the main
  landing page experience
- Add clear calls to action and route handoffs for:
  - request beta access
  - sign in if already approved
  - open the read-only demo experience
- Make sure public users are not dropped into raw auth or request-form screens
  without enough context to understand what happens next
- Align the welcome/demo flow with the landing-page narrative and visual
  direction rather than treating it as a separate mini-product
- Make sure the public entry flow works cleanly on desktop and mobile

## Out of Scope

- The hero landing-page layout, premium motion direction, and scroll storytelling
  work itself
- Deep marketing-site content such as long-form feature pages, blog/news, or
  SEO-heavy content architecture
- Pricing and subscription packaging
- Reworking the approved-user authenticated app shell

## Acceptance Criteria

- Demo, sign-in, and beta-request entry points are easy to find from the public
  surface
- Public users can move between landing, sign-in, access request, and demo
  paths without awkward dead ends or context loss
- Public copy and routing set realistic expectations about provider support and
  current beta shape
- Desktop and mobile public entry flows feel intentional and production-ready
