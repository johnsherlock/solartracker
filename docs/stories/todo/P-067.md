# P-067: Send historical backfill completion notifications

## Objective

Notify users when their initial historical provider backfill has completed so
they know the app is ready for meaningful exploration after signup.

## Scope

- Trigger a notification when the initial signup-era backfill finishes for an
  installation
- Ensure the notification only fires for meaningful completion states rather
  than for every small retry or chunk
- Include clear wording about what is now available in the product and where
  the user should go next
- Respect the user's saved notification preferences where applicable
- Record enough delivery metadata to support support/debugging if a user says
  they never received the completion email

## Out of Scope

- Designing the full onboarding backfill workflow itself
- In-app notification center work
- Rich multi-step drip campaigns after backfill completion

## Acceptance Criteria

- A user can receive a backfill-complete notification after their initial
  history load finishes successfully
- Duplicate completion emails are not sent for the same completed backfill
- The notification points the user back into a useful signed-in entry point
  such as Overview, Live, or Range History
- Delivery metadata is available for operator troubleshooting

## Dependencies

- `FE-018`
- Automated historical backfill workflow
- Existing Settings notification preferences
