# P-084: Add admin waitlist invite sending and resend tracking

## Objective

Turn the existing admin waitlist screen into a real beta invite tool so admins
can send the first invite email from the waitlist, resend it when needed, and
see basic invite history directly in the UI.

## Scope

- Extend `waitlist_entries` to track invite state, including:
  - `invited_at`
  - `last_invited_at`
  - `invite_count`
- Add a server action that:
  - sends the invite email to the waitlist entry
  - stamps the invite metadata on the row
  - increments resend count safely
- Update the admin waitlist UI to:
  - show a `Send invite` action for never-invited entries
  - show a `Resend` action for previously invited entries
  - display invite status clearly, such as `Pending` vs `Invited`
  - display the relevant invite timestamp(s)
- Keep the flow lightweight and operator-friendly for the small beta

## Out of Scope

- Tokenized invite links or claim-code workflows
- Full CRM-style waitlist management
- Rich templating, segmentation, or campaign analytics
- Replacing the existing approval flow for signed-in `awaiting_approval` users

## Acceptance Criteria

- `waitlist_entries` stores the first invite time, most recent invite time, and
  invite count
- Admins can send an invite email directly from the waitlist screen
- Invited entries switch from `Send invite` to `Resend`
- The UI shows enough status detail that an admin can tell whether an entry has
  never been invited or has already been invited before
- Resending an invite updates the invite metadata safely and predictably

## Dependencies

- `FE-018`
- Existing waitlist table and `/admin/waitlist` screen
- Existing email delivery path used elsewhere in the app

## Notes

- This is a beta-rollout-critical notification flow, not a generic marketing or
  lifecycle email feature.
- Keep the data model simple but useful: enough metadata for support and basic
  operator confidence without turning the waitlist into a separate system.
