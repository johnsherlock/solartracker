# P-081: Add beta support and bug-report contact flow

## Objective

Give prospective and signed-in beta users a clear way to contact support or
report bugs using a lightweight email-first flow that is easy to operate during
the first small beta.

## Scope

- Add a first-pass support / bug-report entry point on the public side of the
  product
- Add a support / bug-report entry point inside the signed-in app
- Define the first-pass behavior for the contact flow, such as:
  - mailto link to a managed inbox
  - lightweight contact form that forwards to a managed inbox
- Ensure the user receives enough guidance to send a useful report, including:
  - what went wrong
  - which page or flow they were using
  - how to be contacted back if needed
- Keep the route to support easy to find in both onboarding and normal product
  use

## Out of Scope

- Full ticketing-system integration
- Rich support case management inside the app
- Automated screenshot or device-diagnostics capture unless it falls out almost
  for free from the chosen first-pass implementation

## Acceptance Criteria

- Public and signed-in users can find a clear support / bug-report path
- The first-pass flow routes to an operator-managed support inbox
- The UX makes clear what the support path is for and what useful information a
  report should include
- The flow is lightweight enough to operate during a small beta without
  becoming a tooling project of its own

## Dependencies

- `FE-019`
- `FE-012` for deployed email/runtime context

## Notes

- Prefer a simple reliable first pass over a more elaborate workflow. The main
  beta need is that users are not stranded when something goes wrong.
