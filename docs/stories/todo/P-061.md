# P-061: Persist estimated daily backfill for missing range-history days

## Objective

Add a backend estimation and persistence path that can backfill missing
historical days with clearly flagged estimated daily values for `Range History`
while preserving measured raw data as the source of truth.

## Scope

- Design a persisted day-level estimate model for missing days
- Store estimated values separately from measured day-level summaries
- Include explicit metadata such as:
  - `isEstimated`
  - estimate method / provenance
  - confidence bucket or similar trust signal
- Add a job or asynchronous backfill path that can identify missing days and
  compute first-pass estimated daily values
- Support estimation inputs defined by `U-056`, such as neighbouring days,
  seasonal analogs, and optional weather-informed generation estimates
- Make estimated day-level values available to the `Range History` read path
  without altering the Historical Day source data model

## Out of Scope

- Rendering the estimates in the Range UI
- Reconstructing minute-level or half-hour synthetic day detail
- Replacing or mutating measured interval readings

## Acceptance Criteria

- Missing historical days can have persisted estimated day-level values
- Persisted estimated values are explicitly flagged and carry provenance
  metadata
- The estimation path does not overwrite or masquerade as measured raw data
- The range-facing read model can distinguish:
  - measured day
  - estimated day
  - truly missing / no-estimate day
- The estimation job/path is idempotent enough to rerun safely when logic
  changes or better inputs become available

## Dependencies

- `U-056`
- Existing raw interval/day-level reporting source-of-truth layers
