# P-060: Invalidate and rebuild priced daily rollups after tariff edits

## Objective

Make the new Range History daily priced rollup trustworthy by ensuring tariff
edits can invalidate affected historical rollups and asynchronously rebuild
them from raw half-hour interval data.

## Scope

- Detect when a tariff edit changes historically priced outputs, including:
  - tariff version validity ranges
  - price period rates
  - weekly schedule assignments
  - fixed-charge history relevant to priced daily outputs
- Determine the affected installation and historical date range
- Mark the affected daily priced rollups stale or otherwise queued for rebuild
- Add an asynchronous rebuild path that recomputes the affected days from raw
  `interval_readings`
- Ensure the normal range read path does not silently serve known-stale rollups
  as if they were fresh
- Define how rebuild status is surfaced in logs or job metadata for operator
  visibility

## Out of Scope

- Reworking tariff editor UX beyond whatever minimal trigger/wiring is required
- `All` mode optimization
- Replacing raw interval storage
- Supplier-bill reconciliation

## Acceptance Criteria

- Editing tariff history can invalidate affected historical priced daily
  rollups for the relevant installation and date range
- Rebuild runs asynchronously from raw `interval_readings`
- The rebuild path refreshes the same day-level outputs consumed by Range
  History
- The system has a defined way to avoid treating known-stale rollups as fresh
- Operator-visible metadata or logging exists so rebuild activity can be
  inspected when needed

## Dependencies

- `P-059` priced daily rollup for Range History
- Existing tariff editing flows and background job patterns
- **Decision 0009** (interval_readings retention strategy) — **must be resolved
  before implementation begins**

## Prerequisite Decision

This story currently assumes rollup rebuilds read from locally stored
`interval_readings`. That assumption is under active review in decision record
`docs/decisions/0009-interval-readings-retention-strategy.md`.

The decision affects:

- whether the rebuild path reads local rows or re-fetches from the MyEnergi API
- whether a `stale` column is needed on `daily_priced_rollups`
- how long `interval_readings` are retained (which determines rebuild coverage)

Do not implement P-060 until decision 0009 is resolved. The acceptance criteria
and out-of-scope clause ("Replacing raw interval storage") may need updating
once the retention strategy is chosen.
