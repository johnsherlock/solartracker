# FE-017: Overview and Signed-in Landing

## Goal

Turn the intended Overview screen into the product's real signed-in landing
experience in `apps/web`, so users arrive at a calm high-level summary of
financial outcome, setup progress, trust/freshness, and next actions instead of
dropping straight into a more tactical page.

## Status

`Todo`

## Feature Completion Criteria

- A signed-in default landing screen exists that answers "am I saving money, and
  can I trust what I am seeing?" without requiring users to interpret charts
  first
- The screen surfaces high-level finance state, setup progress, live snapshot
  context, and next-step CTAs in a coherent summary-first layout
- Provider-only or setup-incomplete users still see a useful, non-broken
  landing state with clear unlock messaging
- Navigation between Overview, Live, Historical Day, Range History, Tariffs,
  and Data Health feels intentional rather than like separate prototype slices
- Live and History pages are revisited after Overview lands so overlapping copy,
  CTAs, and entry-point assumptions are tidied up

## Deferred From This Feature

- Public landing, beta-access, and demo-mode work (`FE-009`)
- Annual wrap-up or digest concepts

- Battery what-if or other advanced recommendation engines

## Notes

- Live can remain the temporary authenticated entry point until this feature is
  implemented, but Overview is the intended long-term default signed-in home.
- Keep Overview summary-first and decision-first. It should synthesize the app,
  not become another dense dashboard.
