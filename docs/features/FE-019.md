# FE-019: Beta Rollout Must-Haves

## Goal

Close the remaining cross-cutting gaps between "the app basically works" and
"we can confidently onboard a few real beta users" by adding the launch
plumbing, support touchpoints, in-app guidance, and targeted polish that do not
fit cleanly inside one existing feature.

This feature is intentionally narrow: it should capture the missing pieces that
make the beta feel operable, understandable, and supportable without reopening
major product architecture or broadening the release into a bigger v1 launch.

For rollout planning, this feature also acts as the umbrella execution view for
the first beta path even when some supporting stories still formally belong to
`FE-012` or `FE-018`.

## Status

`Todo`

## Feature Completion Criteria

- The non-code beta setup steps for domain, secrets, callbacks, cron auth,
  email sender, and launch/recovery checks are documented and explicit
- The canonical beta domain exists and the external ownership/setup required by
  Vercel, Google OAuth, and email delivery is no longer an open blocker
- Successful provider setup automatically leads into a supportable onboarding
  backfill flow without requiring manual operator intervention
- The product has a lightweight first-pass support / bug-report path that real
  beta users can find without needing personal backchannel access
- Main user-facing pages have concise contextual help so new users understand
  what each surface is for and how to interpret it
- Settings and onboarding flows explain why accurate tariff, finance, and
  location inputs materially improve the product's value
- Known first-beta polish issues from product review have one controlled home
  and are addressed without turning into an open-ended redesign effort

## Dependencies

- `FE-009` for the public landing and unauthenticated entry path
- `FE-012` for deployment, release workflow, and email/runtime setup
- `FE-014` for setup domains whose user value needs clearer explanation
- `FE-018` for invite and notification behavior that follows once rollout
  plumbing is in place

## Deferred From This Feature

- Full customer-support tooling or ticket-management systems
- Long guided onboarding tours, walkthrough engines, or analytics-heavy product
  education systems
- Large-scale visual redesign work beyond the agreed launch-blocking polish list
- Marketing-site depth beyond what the first public beta entry flow needs

## Notes

- This feature complements `FE-009`, `FE-012`, and `FE-018`; it does not
  replace them.
- `FE-017` Overview is intentionally not a first-beta blocker right now; Live
  can remain the signed-in landing page for the initial rollout.
- The intended outcome is a beta that feels deliberate and supportable, not a
  marketing-perfect launch.
- Keep the first-pass help and support treatment lightweight and maintainable:
  short explainers, clear contact routes, and explicit launch notes beat a
  more elaborate system that is hard to keep current.
