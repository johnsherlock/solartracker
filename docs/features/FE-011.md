# FE-011: Calendar View

## Goal

Add a calendar-based way to browse history so users can move through days,
inspect gaps or standout periods quickly, and navigate historical data using a
time-native interaction instead of only date pickers and range charts.

The first slice should behave like a real year-at-a-glance history surface
rather than a generic date picker: users should be able to read daily patterns,
swap between several energy and value metrics, and jump directly into day or
range detail from the same screen.

## Status

`Todo`

## Feature Completion Criteria

- A dedicated calendar-history surface exists with clear navigation rules
- Users can move between calendar selection, single-day detail, and range views
  without losing context
- The calendar presentation makes missing data, unusual days, and browsing
  state legible at a glance
- Users can scan a whole year of daily performance in one view rather than
  paging month by month
- The active metric can switch between energy and value categories without
  forcing a page reload
- Calendar View and Range History share yearly cached data so year-scale
  browsing feels coherent across both surfaces

## Dependencies

- `FE-003` for the dedicated Historical Day destination
- `FE-006` for range navigation targets and shared range-year data
- `FE-005` / `P-056` for the interval-backed yearly range payloads the
  calendar surface consumes

## Deferred From This Feature

- Annual wrap-up and engagement-style recap experiences
- Ranking, percentile, or AI-generated highlight systems unless they are needed
  directly for the calendar interaction
- Editable annotations or note-taking on specific days
- Cross-year comparison dashboards or side-by-side heatmaps

## Notes

- The first implementation should prefer reusing the existing yearly range
  payload contract instead of creating a separate calendar-specific backend.
- The intended interaction model is:
  - day click -> Historical Day
  - month click -> monthly Range History
  - year click -> yearly Range History
- This feature should feel complementary to Range History, not like a second
  analytics dashboard competing with it.
